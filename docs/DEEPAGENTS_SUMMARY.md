# DeepAgents 框架核心特性总结

本文档旨在总结 `deepagents` 框架的核心组件，特别是主 Agent、子 Agent（通过 `task` 工具实现）以及文件系统工具集的功能和交互模式。

---

## 1. 主 Agent (Orchestrator)

主 Agent 是整个任务流程的**核心协调者**。它直接与用户交互，管理顶层状态，并决定何时自己执行任务，何时将任务委派给专门的子 Agent。

### 核心能力：

*   **状态管理**: 维护整个任务的全局状态，包括：
    *   `messages`: 完整的对话历史。
    *   `todos`: 结构化的任务列表（通过 `todoListMiddleware`）。
    *   `files`: 一个虚拟的文件系统状态（通过 `createFilesystemMiddleware`）。
*   **工具集**: 可以访问所有注册的工具，包括文件系统工具、`task` 工具（用于创建子 Agent）以及任何用户自定义的工具。
*   **长时记忆**: 通过 `summarizationMiddleware` 自动压缩旧的对话历史，使其能够在不超出上下文窗口限制的情况下处理非常长的对话。
*   **鲁棒性**: 通过 `createPatchToolCallsMiddleware` 自动修复因中断或取消而产生的“悬空”工具调用，确保对话历史的连贯性。

### 关键行为：

主 Agent 的主要职责是**规划和调度**。它会分析用户请求，将其分解为步骤，然后决定：
1.  直接调用工具（例如 `read_file`）来完成简单、原子性的任务。
2.  调用 `task` 工具，将一个复杂的、独立的子任务**委派**给子 Agent 去执行。

---

## 2. 子 Agent (Subagents / `task` 工具)

子 Agent 是被主 Agent 按需创建的**临时性、专门化的执行单元**。它们通过一个名为 `task` 的特殊工具被调用。

### 调用与生命周期：

1.  **调用**: 主 Agent 通过调用 `task` 工具来启动一个子 Agent。调用时必须提供：
    *   `subagent_type`: 要使用的子 Agent 类型（默认为 `general-purpose`）。
    *   `description`: 一个详尽的、自包含的任务描述，作为子 Agent 的初始 `HumanMessage`。
2.  **执行**: 子 Agent 在一个**隔离的上下文**中自主运行。它拥有自己独立的 `messages` 历史，并继承了主 Agent 的一部分状态（如文件系统），但关键状态（如 `todos`）被隔离。
3.  **返回**: 完成任务后，子 Agent 将其最终结果作为 `ToolMessage` 返回给主 Agent。这个结果通常是任务的摘要或产出。
4.  **销毁**: 子 Agent 在返回结果后立即被销毁。它是一个**完全无状态的、一次性的**执行过程。主 Agent 无法在后续的回合中与同一个子 Agent 继续对话。

### 核心特性与限制：

*   **✅ 并发执行 (Parallel Execution)**:
    这是 `deepagents` 最强大的特性之一。主 Agent 可以在**单轮对话**中，通过发出多个 `task` 工具调用来**同时启动多个子 Agent**。这些子 Agent 会并行执行，这对于处理可以分解为多个独立部分（例如，同时研究三个不同主题）的复杂任务至关重要。

*   **✅ 上下文隔离 (Context Isolation)**:
    子 Agent 的执行过程（包括其内部的工具调用和思考链）对主 Agent 是一个**“黑盒”**。这种隔离可以防止子任务的大量中间步骤污染主 Agent 的上下文窗口，使其保持专注和高效。

*   **⚠️ 追踪挑战 (Tracking Challenge)**:
    由于并发和黑盒特性，从主 Agent 的事件流中追踪哪个子 Agent 刚好完成任务是困难的。简单的堆栈模型会失效。正确的追踪方式是依赖 `on_tool_start` 和 `on_tool_end` 事件中提供的 `tool_call_id`，将它与一个在 `task` 调用时生成的内部 `agentId` 关联起来，从而准确地识别出完成任务的并发实例。

*   **⚠️ 内部可见性限制**:
    主 Agent 的事件流**只能监听到子 Agent 任务的开始 (`on_tool_start`) 和结束 (`on_tool_end`)**。子 Agent 在其隔离环境中执行的*具体内部步骤*（例如，它自己调用的 `read_file` 或 `internet_search`）对于主 Agent 的事件监听器是**不可见的**。

## 3. 文件系统工具集

`deepagents` 提供了一套功能强大的虚拟文件系统工具，使 Agent 能够像开发者一样与文件交互。

| 工具 (`Tool`)         | 描述 (`Description`)                                                                   |
| --------------------- | -------------------------------------------------------------------------------------- |
| `ls`                  | 列出指定目录下的文件和子目录。                                                         |
| `read_file`           | 读取文件的内容。支持分页（`offset` 和 `limit`），便于处理大文件。                       |
| `write_file`          | 创建一个新文件并写入内容。如果文件已存在，则会报错。                                   |
| `edit_file`           | 编辑一个已存在的文件，通过精确的字符串查找和替换来修改内容。                             |
| `glob`                | 使用 glob 模式（例如 `**/*.js`）查找匹配的文件路径。                                    |
| `grep`                | 在文件内容中搜索正则表达式模式，并返回匹配的行号和内容。                                 |
